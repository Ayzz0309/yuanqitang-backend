# yuanqitang-backend

## v2.1.6 自訂優惠券與批量發放版

這個版本包含完整前端 `index.html`、Render 後端與 Firestore 規則。

### 本版重點

- 客人可一次複選多個服務項目，總時間、金額、師傅排班及床位衝突會一併檢查。
- 移除多出的 40 分鐘項目，並統一預約介面的服務名稱用語。
- 內建 2026 年 10 月紙本班表，支援 `16:30`、`20:30` 等半小時班別。
- 接案、建立預約、打卡、公休日與班表改用 Firestore 交易，降低多裝置同時操作造成的覆蓋或重複資料。
- 倒數到期停在 `00:00` 並只提醒一次；服務仍須由承接人、管理人員或店長確認切單，避免系統自動結帳造成金額錯誤。
- 實際開始、結束與加時會同步床位占用；跨午夜服務與打卡改用時間戳計算。
- 客人預約狀態與可預約時段會即時同步，並避免即時更新清掉尚未送出的手動預約表單。
- LINE Webhook 增加簽章驗證，通知 API 增加限流、輸入限制、逾時與來源限制。

### 店長權限與月報功能

- 界面中的管理者稱號改為「店長」，程式內部角色值仍保留 `boss` 以相容舊資料。
- 新增 `manager` 管理人員角色：可建立、安排、接受、修改與取消預約。
- 一般員工可查看所有待確認預約並截圖詢問，但不能接受、婉拒、指派或修改。
- 已安排案件只由店長、管理人員與實際承接員工執行開始、加時與切單。
- 報表支援按月份切換，歷史預約保留在 Firestore，可隨時回看各月營收、案件與員工業績。
- 報表、員工權限、班表編輯與系統設定仍只有店長可修改。
- 公開的 `index.html` 不再內建固定店長密碼；店長登入一律使用 Firebase 中的正式帳號，若帳號資料不存在可用原有 `BOSS_RECOVERY_CODE` 重設並安全重建。
- 店長可在「員工」頁將帳號設為管理人員，操作時使用現有 `BOSS_RECOVERY_CODE` 確認，無需新增環境變數。
- 店長可在每個員工帳號旁指定刪除單一帳號，不再從畫面一次刪除全部員工；店長帳號永遠不能刪除。
- 刪除員工只移除登入帳號，已有預約、報表、班表與打卡歷史保留，原班表身分可重新註冊。
- 客人預約時段改為 09:30–22:00 每 10 分鐘連續列出，並依當日實際班表、服務總時長與床位衝突判斷可否預約，不再錯誤封鎖 14:00–19:00。

### 客人帳號與優惠券

- 店長「客人」頁會列出所有可登入帳號與僅有歷史的客人，可展開查看逐筆已完成消費、優惠折抵、實收金額與服務人員。
- 可以指定刪除單一客人登入帳號，需使用原有 `BOSS_RECOVERY_CODE`；預約、消費與報表歷史保留。
- 現場手動建立的客人資料，之後用同一手機註冊時會原地升級成可登入帳號，不會因舊資料卡住。
- 客人自行註冊一律需要 09 開頭的 10 碼手機；店長手動選擇「會員」時也強制填寫有效手機，並保存會員狀態，供下一階段串接預約簡訊。一般非會員現場預約仍可不填手機。
- 優惠券活動與客人所得的單張券分開儲存；發券時將條件快照存進客人錢包，日後修改活動不會改到舊券。
- 每個活動每人限領一張，後端另以「活動＋手機雜湊」留存防重複紀錄，刪除帳號再註冊也不能重領同一活動；支援固定金額、百分比、最低消費、最高折抵、有效期、總發行上限、新客首次預約與回訪客條件。
- 店長可建立自訂優惠券，優惠碼可手動輸入或一鍵自動產生；每張活動可設定「全部服務都能折」或複選一個以上的指定服務，指定服務券只計算符合項目的小計，不會誤折同筆預約中的其他項目。
- 客人會在送出預約前選擇錢包內可用優惠券，畫面即時計算原價、折抵與應付金額；不符合服務、期限、最低消費或使用資格時不能送出。
- 店長與管理人員在接案卡會看到醒目的優惠券區塊，清楚顯示券名、代碼、適用範圍、原價、折抵、應收金額及目前是已鎖定、已退回或已核銷。
- 店長「客人」頁可先選活動，再對單一客人發放，或一次發給「全部會員」／「全部有有效手機的客人」；批量發放會跳過同活動已領取、手機無效或其他不符合條件者。系統自動新會員券禁止批量發放，避免舊會員誤領。
- 預約時優惠券先變成「已鎖定」；客人取消、店家婉拒或取消會退回，切單完成時才變成「已使用」。
- 後端部署後會補上舊版已有的 `YUANQI100`、`NEW200`、`VIP10` 三個活動，但預設為「停用」；店長確認金額與條件後才手動啟用，避免公開的舊測試碼突然產生實際折抵。
- 新增「頌缽音波課程（一對一）」60 分鐘 NT$2,000、120 分鐘 NT$4,000，並新增獨立的「頌缽音波」預約分類。
- 新會員完成註冊或由店長現場登記成會員後，系統會自動發送一張 `NEW_MEMBER_BOWL90`「頌缽音波課程 9 折體驗券」。固定活動碼不能由客人手動輸入領取，避免舊會員自行領券；發券異常時店長仍可人工補發，但同手機限一張的紀錄不會清除。
- 每個手機號碼終身限領一張，刪除帳號再註冊也不能重領；每張券只能核銷一次，領取日起 60 天內的預約才可使用。
- 此券只折抵「頌缽音波課程」項目的 10%；同一預約若另選其他服務，其他服務仍按原價計算。每筆預約只能選一張券，不得併用、折現或找零。
- 客人「優惠券」頁有獨立使用區，可直接前往指定課程；預約送出時鎖券，取消或婉拒會退回，完成切單才核銷。已鎖券的預約不能直接改成其他服務，需先取消退券後重新預約。
- 手機目前為會員註冊必填並檢查台灣 09 開頭 10 碼格式；本版尚未加入簡訊 OTP，因此只限制號碼格式與每號限領，尚未驗證號碼實際持有人。

### Render 環境變數

- `EMPLOYEE_REGISTRATION_CODE`：店內員工註冊碼。
- `BOSS_RECOVERY_CODE`：店長帳號救援與員工權限管理碼，必須與員工註冊碼不同且不可提供給員工。
- `FIREBASE_SERVICE_ACCOUNT_JSON`：Firebase 服務帳戶 JSON 的完整內容。
- `LINE_CHANNEL_ACCESS_TOKEN`：LINE Messaging API Channel Access Token。
- `LINE_CHANNEL_SECRET`：LINE Messaging API Channel Secret；Webhook 驗章必填。
- `STAFF_GROUP_ID`：員工通知群組 ID。
- `CUSTOMER_GROUP_ID`：客人通知群組 ID。
- `ALLOWED_ORIGINS`：允許呼叫後端的網站來源，多個來源用逗號分隔。預設為 `https://ayzz0309.github.io`。
- `LOG_LINE_SOURCE_IDS`：只有在取得 LINE 群組 ID 時暫時設成 `true`，完成後請改回 `false` 或刪除。

## v2.1.3 員工權限修正

- 員工註冊時必須選擇對應班表身分，同一身分不可重複綁定。
- 一般員工可看所有待確認預約，但只會看到自己的已接預約與今日案件。
- 一般員工只能替自己打卡，且不會看到手動預約功能。
- 管理人員可管理預約；報表、客人名單、LINE 紀錄、員工管理、公休與班表修改僅限店長。
- 店長可在報表的完成紀錄中修正實收金額。
- Firestore 過渡規則禁止員工帳號自行更改 `role` 或帳號 ID。
- 忘記店長帳號或密碼時，可透過獨立 `BOSS_RECOVERY_CODE` 重設並取回帳號 ID。

### 尚未自動變更的安全架構

目前既有帳號仍使用舊版欄位登入，部分 Firestore 集合也仍需讓前端直接讀寫。全面改成 Firebase Authentication 需要搬移既有帳號與重新設計權限，這次未自動處理，以免造成現有客人及員工無法登入。正式長期使用前，建議另開版本完成 Firebase Auth 與最小權限規則遷移。
